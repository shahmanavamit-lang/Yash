The problem

Continuously arriving data is hard to inspect by repeatedly processing its entire history. StreamWatch explores how a recent-data window and fast per-sensor tracking can detect unusual values while keeping memory bounded.

The proposed system

Each new reading is compared with its sensor’s recent baseline. Java assigns an anomaly score, updates the window and hash table, and uses a min-heap to select the most significant active alerts. This browser interface makes every stage visible.

Incoming reading→Window + hash state→Anomaly score→Min-heap→Top-K alerts

Why rebuild the ranking?

When an old winner expires, another active anomaly must take its place. Rebuilding from the bounded window guarantees correct results. O(log K) describes one heap operation; the full snapshot costs O(W log(K+1)). Total analysis memory is O(W + U + K), where U is the active sensor count.

What this demo covers

Generated or manual input, per-sensor warm-up, recent-window tracking, anomaly detection, and ranked output. Arrival scores remain fixed until expiration. This is an educational simulator; live external feeds, databases, and production big-data throughput are outside its scope.
